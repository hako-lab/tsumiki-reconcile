1. BOOTHの注文CSV

BOOTHの「売上管理CSV」を選択。複数ファイル可。UTF-8 / UTF-8 BOM / Shift-JIS、合計10MBまで。

重複と金額の扱い

同じ注文番号・商品ID・バリエーションの完全一致明細は1回だけ数えます。値が違う重複は集計を止めます。注文状況・受取金額・発送日時は注文単位で1つにまとめ、相反する値はエラーにします。受取金額はCSV記載額で、実際の銀行振込額ではありません。小計にBOOSTを独自加算しません。ここでの小計は元CSVの小計合計であり、税務上の売上認定はしません。

2. 通販と会場を合わせた在庫

商品IDとバリエーション名をBOOTHと同じ表記にします。基準在庫は、取り込む期間の直前に数えた数。会場販売数は返品前の数量です。献本・破損を販売に含めません。

予定残数 = 基準在庫 + 追加 − BOOTH発送済み − 会場販売 + 会場返品 − 無償配布 − 破損紛失

3. 即売会だけの売上と現金

独立して記録した販売額と、支払い方法別の受取額を照合します。通販の受取金額は混ぜません。各受取額は返金差引後で入力。

予定現金 = 開始釣銭 + 現金補充 + 現金受取 − 現金回収。カード受取は銀行入金額ではありません。現金から直接払った経費は現金回収へ含めて記録してください。

結果を手元へ

出力には読み込んだユーザー識別コード・氏名・連絡先を含めません。CSVはExcelでの数式実行を避けるため、危険な先頭文字の文字列にアポストロフィを付けます。注文番号の先頭0はCSV内では保ちますが、Excelで直接開くと変わる場合があります。列を文字列として取り込んでください。

使う前に確認すること・できないこと
  • 同じ注文の列が部分的に重なる別出力を混ぜると、衝突エラーになることがあります。内容を元CSVと照合してください。
  • 発送済みの判定は発送日時の有無です。出荷取り消し、外部返品や不正な日時文字列は判定しません。
  • BOOTHからの返金・キャンセルやイベント外の在庫移動は、自分で対象を整理してください。発送日時が付いた取消注文を対象にすると数量に含まれます。
  • 同じ実在商品に複数の商品IDがある場合や、表記ゆれは自動統合しません。
  • 在庫の基準日とCSV対象期間を揃えてください。未発送の注文は予約在庫ではなく、発送前数量として表示するだけです。
  • 金額の異なる過去イベント、値引き、商品別利益、会計ソフト取込、税・確定申告、在庫同期には対応しません。
  • 差異0は記録全体の正しさを保証しません。同じ数を両側に写しただけでは照合になりません。
  • 本品は業務確認の補助です。元データと独立した現物/現金の確認を行ってください。
